# TRACK-HUD – Architektur-Vertrag

Verbindlich für alle Arbeitspakete aus `docs/plans/TRACK-HUD.json`. Änderungen nur durch das Integrationspaket hud-p7-final.

- Paket @faf/hud (packages/hud): Quell-Export „.“ → ./src/index.ts, „./styles.css“ → ./src/styles/index.css. Laufzeit-Deps nur preact, @preact/signals, @fontsource/ibm-plex-sans-condensed, @fontsource/ibm-plex-mono. src/ importiert KEIN Workspace-Paket (dep-cruiser-Regel hud-deps); Datenanbindung ausschließlich über HudModel (Signals) + HudCommands (Callbacks). Nie sim/client/render/protocol importieren.
- Ordner: src/model/<sektion>.ts (Typen + Signals der Sektion + create<Sektion>Section() mit Defaults + reine Ableitungsfunktionen), src/model/index.ts (HudModel-Aggregat, createHudModel(), HudProvider, useHud(), useCommands()), src/commands/<sektion>.ts (Callback-Interfaces) + src/commands/index.ts (HudCommands = Vereinigung aller Sektionen, createNoopCommands(), createRecordingCommands()), src/i18n (t, tn, locale, setLocale, Tabellen src/i18n/locales/<ns>.de.json/.en.json), src/format (Zahl/Zeit DE/EN), src/ui (Primitive, keys.ts), src/styles (fonts.css, tokens.css, base.css, index.css), src/data (generierte Roster-/Icon-Daten, Card-Logik, unitText), src/hud/{top,selection,card,strip,minimap,root} (HUD), src/menus/{main,skirmish,loading,gamemenu,settings,score}, src/scheduler, src/demo/<gruppe>.ts (deterministische Demo-/Fake-Daten, eigener seeded PRNG aus src/demo/core.ts, kein Math.random). Jede Gruppe exportiert über ihre eigene index.ts; src/index.ts re-exportiert alle Gruppen-Barrels (von p0 angelegt).
- Sektion/Namespace → Eigentümer: model+commands+i18n-Namespace eco, status, alerts, tooltip → p2-top; selection, factory → p3-selection; card, orders, strip → p4-card; minimap, snapshot (+Namespace hud) → p5-root; menus/* (Namespaces menu, skirmish, loading, gamemenu, settings, score) → p6-menus; common → p0. Der Eigentümer darf seine Sektionsdateien/Namespaces erweitern; fremde nie. Unit-Namen/Rollen/Kurznamen/Beschreibungen/Nachbarschaft stehen NICHT in den i18n-Tabellen, sondern kommen über unitText(id, field, locale) aus src/data (P12-Key-Schema unit.core.<id>.<field>).
- i18n: Keys sind volle Pfade („ui.eco.flow“); DE ist Quelle, EN wird per Typ gegen DE geprüft (fehlender Key = tsc-Fehler = Build-Bruch). Platzhalter {name}; Plural über <key>.one/<key>.other + tn(). Keine hartkodierten UI-Strings in .tsx (Scanner-Test aus p0). Locale „pseudo“ (+30 % Länge, Klammern) für Layoutprüfung.
- Galerie apps/hud-gallery (@faf/hud-gallery, Vite + Preact): Stories in src/stories/<gruppe>.stories.tsx, default export readonly Story[] (Vertrag src/story.ts: interface Story { id: string (global eindeutig, kebab-case, z. B. „resource-meter--stall“); component: string (Name aus ui.md §6); state: string (Zustandsname aus ui.md §6, deutsch wie dort); title: string; layout: 'component' | 'fullscreen'; viewport?: { width: number; height: number } (Standard fullscreen 1920×1080, component 960×640); scale?: number; tags?: readonly string[] ('xbrowser', 'perf', 'no-pseudo'); nodeBudget?: number; setup?(ctx: StoryContext): void | (() => void); render(ctx: StoryContext): ComponentChildren } mit StoryContext { model: HudModel; commands: HudCommands; log: RecordedCall[] }). Registrierung automatisch per import.meta.glob. Route #/story/<id>?locale=de|en|pseudo&scale=<n>&teams=house|relation|cvd&motion=reduce&shot=1. E2E: vite build + vite preview auf Port FAF_HUD_E2E_PORT (Standard 4483, strictPort), Playwright chromium/firefox/webkit, workers 1; Screenshots nach test-results/hud-gallery/<browser>/<id>.png (nicht eingecheckt).
- Tests: packages/hud/test/<gruppe>/*.test.{ts,tsx}; DOM-Tests beginnen mit // @vitest-environment happy-dom und nutzen renderWithHud()/cleanup aus packages/hud/test/support (p0). Jede interaktive Fläche wird mit createRecordingCommands() auf den richtigen Command geprüft.
- Styling: nur Tokens (tokens.css = 1:1 docs/design/ui-mockups/assets/tokens.css), Klassen/Markup wie Mockups (ff-panel, ff-cell, is-active, is-armed, is-stall …), data-component=<Komponentenname>, data-testid an jeder Komponente, data-panel an HUD-Panels (Layoutprüfung), data-fit an Beschriftungen, die nicht abgeschnitten werden dürfen. §9.2: im Update-Pfad nur textContent/Klassen/CSS-Variablen, Balken per transform: scaleX(var(--v)), contain auf Panels, keine Layout-Lesezugriffe, Animation nur opacity/transform, prefers-reduced-motion/data-motion=reduce respektieren. Hot-Werte (10/4 Hz) als Signals direkt in JSX binden (kein Re-Render der Komponente).
